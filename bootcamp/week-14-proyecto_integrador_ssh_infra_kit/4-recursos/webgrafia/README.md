# Webgrafía — Semana 14

| Recurso | Descripción |
|---------|-------------|
| [Effective Troubleshooting (Google SRE Book)](https://sre.google/sre-book/effective-troubleshooting/) | El método de diagnóstico de la teoría 03: observar, formular hipótesis, comprobarlas. Lo que haces con `bin/doctor` y `romper.sh` |
| [Managing Incidents (Google SRE Book)](https://sre.google/sre-book/managing-incidents/) | Cómo se lleva un incidente con varias personas: roles, comunicación y un documento vivo. El siguiente paso del RUNBOOK |
| [Threat Modeling (OWASP)](https://owasp.org/www-community/Threat_Modeling) | Qué es un modelo de amenazas, sus cuatro preguntas y los métodos más usados (STRIDE, árboles de ataque) |
| [Threat Modeling Manifesto](https://www.threatmodelingmanifesto.org/) | Valores y principios del modelado de amenazas, en una página |
| [Diátaxis](https://diataxis.fr/) | Cuatro tipos de documentación (tutorial, guía práctica, referencia, explicación): el README, el RUNBOOK y los comentarios del kit encajan en ellos |
| [ShellCheck](https://www.shellcheck.net/) | El analizador de `bin/kit-check`; cada aviso tiene su página en la wiki (por ejemplo [SC2016](https://shellcheck.net/wiki/SC2016)) |
| [About secret scanning (GitHub Docs)](https://docs.github.com/en/code-security/secret-scanning/introduction/about-secret-scanning) | La versión de GitHub de la comprobación `secretos`: busca llaves y tokens en cada push y en el historial |
| [Validating tasks: check mode and diff mode (Ansible)](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_checkmode.html) | `--check` y `--diff`, los que usas antes de cada despliegue y para ver si alguien cambió un servidor a mano |
| [OpenSSH guidelines (Mozilla)](https://infosec.mozilla.org/guidelines/openssh) | Una configuración de cliente y servidor de referencia, para comparar con la de tu kit en la defensa |
| [Manuales de OpenSSH](https://www.openssh.com/manual.html) | `ssh_config(5)`, `sshd_config(5)`, `ssh-keygen(1)`: la referencia de cada opción del kit |
